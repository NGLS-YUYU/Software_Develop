## 1. 产品背景与建设目标

### 1.1 背景

高校教务管理需要同时维护学院、专业、班级、学生、教师、课程、培养方案、教学任务、教学班、教室、时间、选课、考试、成绩、评价等数据。人工表格与分散系统容易造成数据不一致、排课冲突、成绩流程不透明和权限越界。

### 1.2 建设目标

- 建立统一账号、角色与权限体系；
- 建立从课程开设到成绩发布的完整教务闭环；
- 让学生、教师、教务在同一系统中按职责协作；
- 对选课、成绩、考试等关键业务提供后端强制校验与事务保护；
- 提供可正式部署、可运维、可审计的 Web 系统；
- 为后续学籍、毕业审核、智能排课等能力保留扩展空间。

### 1.3 成功标准

- 三类角色能独立完成各自核心任务；
- 关键业务规则由后端最终裁决，前端不能绕过；
- 正式环境通过 Nginx + systemd 长期运行；
- 正式数据库迁移可追溯，历史数据不丢失；
- 文档、测试与部署步骤可交付给后续维护者。

## 2. 产品定位和适用范围

### 2.1 产品定位

UAMS 是面向单所高校教学管理场景的**多角色教务业务系统**，不是通用低代码平台，也不是完整的学校信息门户。

### 2.2 适用范围

适用于：

- 高校教务处/二级学院的教学运行管理；
- 课程、教学任务、教学班、排课、选课、成绩、考试等核心业务；
- 课程设计、毕业设计、教学演示与内部试点。

不适用于：

- 招生、财务、宿舍、图书馆、人事、科研、OA 等非教务业务；
- 多学校/多租户 SaaS 运营；
- 原生移动 App；
- 在线直播教学平台；
- 需要复杂智能优化算法的全自动排课。

### 2.3 角色边界

- 学生只访问本人数据；
- 教师只访问本人授课教学班及对应学生；
- 教务管理员管理全校教学业务数据；
- 教师可被授予教务管理员角色，形成双身份，但权限仍以角色为准。

## 3. 用户角色与需求分析

| 角色 | 系统身份 | 核心诉求 | 主要约束 |
|---|---|---|---|
| 学生 | `STUDENT` | 查课表、选课、查成绩/排名、考试、评价、资料 | 仅本人数据；选课受窗口/容量/年级/时间冲突限制 |
| 教师 | `TEACHER` | 管理本人课程、名单、成绩、资料、调停课 | 仅本人教学班；已审核成绩不可直接改 |
| 教务管理员 | `ACADEMIC_ADMIN` | 维护基础数据、开课排课、选课、成绩审核、考试、评价、审计 | 全校范围；关键操作留痕 |

### 3.1 典型使用场景

1. 教务建课、建教学任务、分配教师与教室、开放选课；
2. 学生查看可选课程并选课/退课，形成课表；
3. 教师录入成绩、提交审核；
4. 教务审核/驳回/更正成绩；
5. 教务安排考试、考场与监考，系统检测冲突；
6. 学生查询成绩、GPA、排名与考试安排；
7. 学生提交评价，教务查看统计；
8. 教师上传教学资料，学生下载；
9. 教师提交调停课申请，教务审批后自动调整排课；
10. 教务导出名单/成绩/选课结果，查询操作日志。

### 10.1 选课业务规则

- 必修、公共必修、实践类课程由教务安排，学生不能自主退课；
- 同一学生同一学期同一课程只能选择一个教学班；
- 选课与退课必须在事务中完成，并锁教学班行防超容；
- 窗口关闭、学期非 ACTIVE、年级不符时后端拒绝，前端仅展示原因。

## 22. 需求验收标准

### 22.1 角色验收

| 场景 | 通过条件 |
|---|---|
| 管理员登录 | 用户名 + 个人姓名 + 密码三字段登录；任一不符有统一中文提示 |
| 教师登录 | 进入教师工作台；仅看到本人课程 |
| 学生登录 | 进入学生工作台；仅看到本人数据 |
| 管理员开课—排课—选课 | 创建任务/教学班/排课/窗口后学生可选，容量与冲突正确 |
| 教师成绩闭环 | 录入→提交→教务审核/驳回→学生可查 |
| 成绩更正 | 撤销/更正后历史可查，GPA/排名同步 |
| 考试闭环 | 创建→考场→发布→学生查询；冲突被拒绝 |
| 调停课 | 教师申请→教务批准→课表变化；并发不重复 |
| 资料 | 教师上传→学生下载；越权被拒绝 |
| 审计 | 登录/写操作可在日志查询；无敏感值 |

### 22.2 部署验收

- Nginx 80 首页为 UAMS；
- 子路由直接刷新返回 SPA；
- `/api` 代理到 `127.0.0.1:8000`；
- systemd 后端 active，启动前校验 `uams` 与 Alembic head；
- 5173 不对外提供正式服务；
- 发布失败可回滚，`current` 不因误判被删除。

### 22.3 文档验收

- 本 PRD 与 `PRD.docx` 内容一致；
- 白皮书、技术文档、用户手册、部署指南可打开且链接有效；
- 未实现内容明确标注，不冒充已交付。

## 24. 已知限制与后续规划

### 24.1 已知限制

1. 正式环境当前为 HTTP，尚未配置 HTTPS。
2. 教学资料存本机磁盘，未接入对象存储；多实例需共享存储。
3. 单节点部署，未做高并发、容量与长时间稳定性压测。
4. 评价在数据库保留学生关联，接口只做聚合展示，不是严格匿名。
5. 未接入统一身份认证（CAS/OAuth/LDAP）、短信/邮件通知。
6. 无原生移动端；PC 浏览器优先。
7. 排课为人工排课 + 冲突检测，不含智能优化算法。
8. 无学籍异动、毕业审核、学分预警、教材管理等扩展模块。
9. 日志为追加式，未实现自动归档/保留周期策略。
10. 备份为人工 `mysqldump`，未配置自动定时备份。

### 24.2 后续规划

| 优先级 | 方向 | 说明 |
|---|---|---|
| P1 | HTTPS 与安全加固 | 证书、HSTS、访问控制策略 |
| P1 | 自动备份与恢复演练 | 定时备份、异机保存、恢复验证 |
| P2 | 对象存储/共享文件 | 多实例部署与资料归档 |
| P2 | 邮件/站内通知 | 选课、成绩、考试、调停课通知 |
| P2 | 学籍异动/毕业审核/学分预警 | 扩展教务闭环 |
| P3 | 智能排课/学业分析 | 在真实数据与规则稳定后评估 |
| P3 | 单点登录/多校区 | 视使用单位基础设施 |
