## 4. 关键发现（CRITICAL FINDINGS）

### 🔴 发现 1：TASK-010 批量导入 = BACKEND_ONLY（本次验收最典型问题）

- **问题**：用户无法从系统界面完成任何 Excel 批量导入或模板下载。
- **根因**：后端 `imports.py` 已完整实现 3 个导入接口 + 3 个模板下载（openpyxl 真实生成 `.xlsx`，实测模板下载返回 `5004` 字节、`application/vnd...spreadsheetml.sheet`）；但 `frontend/src/api/index.ts` 中**完全没有 `importApi`**，所有视图（Students.vue / Courses.vue 等）**没有「批量导入」「模板下载」按钮**，菜单/路由中也没有导入页面。
- **影响**：TASK-010 的最终用户（教务管理员）无法完成批量导入流程，任务目标未达成。
- **状态**：BACKEND_ONLY。

### 🔴 发现 2：任务定义漂移 —— 指南与 Git 历史不一致

- **问题**：`docs/V2.0开发指南.md` 只定义 12 个 TASK（TASK-008=课程管理、TASK-011=数据统计、TASK-012=系统部署优化），而 Git 实际提交了 13 个 TASK（TASK-008=教学班基础管理、TASK-011=学期与开课管理、TASK-012=完善开课计划与教学班管理，且多出 TASK-013=教学安排与课表管理）。
- **根因**：开发指南在开发过程中被改写/替换，与真实提交历史脱节。
- **影响**：任何「依据指南的完成结论」都不可信；指南要求的 **TASK-012 系统部署优化（LAN 0.0.0.0 + start.sh）实际上未做**（`DEPLOYMENT.md` 明示「LAN 部署为规划内容，尚未配置」，仓库无 `start.sh`）。

### 🟠 发现 3：多处「后端完成、前端缺入口」的 BACKEND_ONLY 子功能

| 功能 | 后端证据 | 前端缺口 |
|---|---|---|
| 用户管理（TASK-001） | `/users` CRUD + 重置密码 + 停用启用，实测 200 | 无 `userApi`、无 `/admin/users` 路由、无页面 |
| 班级/专业排名（TASK-004/007） | `/grades/my` 返回 `gpa/class_rank/major_rank`，实测 2.78/5/5 | 学生成绩页仅显示 GPA，不显示排名，未调用 `/grades/my` |
| 必修课自动安排（TASK-009） | `POST /teaching-classes/{id}/assign-required` | 前端无 `assignRequired` 调用、无按钮 |
| 学期管理（TASK-011） | `/terms` CRUD + activate/end，实测 200 | 无 `termApi`、无学期管理页（学期仅以字符串下拉出现） |
| 教学安排平铺 API（TASK-013） | `/teaching-schedules` + `/mine` + `/my` + PUT，实测 200 | 前端仍走嵌套 `/teaching-classes/{id}/schedules`，未接平铺端点、无「修改排课」 |

### 🟠 发现 4：成绩权重两套机制冲突，演示数据与现行规则不一致

- **问题**：`Course.regular_weight/final_weight`（默认 0.4/0.6，含 `CHECK regular_weight+final_weight=1.00`）为**死字段**——全后端除 model/schema 外无人引用；真实计算走 `ScoreService.WEIGHT_RULES`（32h→0.2/0.8、48/64h→0.2/0.3/0.5）。
- **证据**：演示数据 grade id=28（PUB101，32h，平时 87 期末 56）的 `total_score=68.40`，等于 `87×0.4+56×0.6`（旧权重）；而现行规则应得 `87×0.2+56×0.8=62.20`。演示数据是在旧权重下种子生成的，与现行计算不一致。
- **影响**：演示数据总评与现行计算规则不一致；课程级权重字段具有误导性且未被使用。

### 🟡 发现 5：测试并非「假覆盖」（正向结论）

- 测试通过 `SessionLocal` 直接打到**同一套 MySQL**（非内存库/SQLite），断言真实数据库状态与业务规则（如 `test_selection.py` 并发用例断言实际选课记录数、`test_teaching_schedule.py` 断言三类冲突错误码），而非仅 `status_code==200`。
- 实测测试自清（`__t13__` 前缀用户/教学班计数均为 0），未污染演示数据。
- 但测试通过**不能**弥补前端入口缺失，因此不改变上述 BACKEND_ONLY/PARTIAL 判定。

## 6. 结论

1. **真正端到端完成（COMPLETE）的只有 5 项**：TASK-002/003/005/006/008。
2. **后端完整、前端无入口（BACKEND_ONLY）1 项**：TASK-010 批量导入——正是本次验收点名的典型问题。
