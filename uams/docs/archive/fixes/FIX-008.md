# FIX-008：成绩权重一致性治理

## 1. 来源

- 来源：V2.1 基线自检发现（不映射单一 TASK，横切 TASK-004/007 正确性）
- 性质：**数据模型 + 数据一致性**问题（死字段 + 陈旧演示数据），与 FIX-001～007 的「后端已有、前端缺入口」完全不同，故单独提出。

## 2. 当前状态

**冲突事实：**

| 机制 | 位置 | 权重 |
| --- | --- | --- |
| 死字段 | `app/models/course.py` `Course.regular_weight` / `final_weight` | 0.4 / 0.6（遗留，未被计算使用） |
| 现行规则 | `app/services/score_service.py` `WEIGHT_RULES` | 32h：平时 0.2 / 期末 0.8；48/64h：0.2 / 0.3 / 0.5；理论+实践=平均 |

**实测证据**：演示数据 grade id=28 `total_score=68.40`，按现行 WEIGHT_RULES（32h）应为 62.2 —— 该行是**按旧 0.4/0.6 权重 seed 的陈旧数据**，非实时计算 bug（`ScoreService.compute` 本身正确）。

**影响链**：`total_score` → 绩点 → GPA → 排名（FIX-002/FIX-003 依赖），陈旧数据会导致绩点/GPA/排名展示与实际规则不符。

## 3. 修复目标

统一成绩权重为**单一数据源**：删除/废弃 `Course.regular_weight`/`final_weight` 死字段，明确 WEIGHT_RULES 为唯一口径，并修复（重新 seed 或重算）现有陈旧演示数据，使 `total_score`/绩点/GPA/排名全部与 WEIGHT_RULES 一致。

## 4. 不在本 FIX 范围内

- 不改变 WEIGHT_RULES 的权重数值（除非 PRD 明确要求，否则以现行 0.2/0.8、0.2/0.3/0.5 为准）；
- 不重写 ScoreService.compute（已正确）；
- 不新增权重维度（如课程类别差异化权重）。

## 5. 需要修改的文件

- `app/models/course.py`（移除 `regular_weight`/`final_weight` 字段定义，或标注废弃）
- 迁移：新增 Alembic migration 删除对应列（**禁止删除既有迁移历史**，只新增一条 drop-column 迁移）
- `app/schemas/course.py`（如 schema 暴露了这两个字段，一并移除）
- 数据修复：提供一次性脚本/迁移（或重建演示数据）修复陈旧 `total_score`
- 若 `import_service.py` / 任何测试引用了这两个字段，同步更新

## 6. 实现要求

- 全局检索 `regular_weight` / `final_weight` 引用，确认无计算路径仍依赖后删除；
- 迁移只新增、不改写历史；删除列为可逆方向（保留降级说明）；
- 陈旧数据修复需**保留行、只纠正 total_score**（不删历史成绩），并记录修复前后对照；
- 更新 FIX-002/FIX-003 的验收基线（排名/GPA 以修正后数据为准）。

## 7. 验收标准

```
grep regular_weight|final_weight 全仓无计算引用
→ 新迁移删除列成功、历史迁移完好
→ 重算后 grade id=28 total_score 与 WEIGHT_RULES(32h) 一致（62.2）
→ GPA/班级排名/专业排名 用修正后成绩重算一致
→ 全量测试通过（不得修改测试结果本身）
```

## 8. 测试要求

- 迁移测试：up/down 均成功，历史迁移链完整；
- 服务测试：`ScoreService.compute` 按 WEIGHT_RULES 断言（已存在），补充「模型中已无死字段」断言；
- 数据一致性测试：抽查多条历史成绩 total_score 与重算一致。

## 9. Git 提交要求

```
fix(FIX-008): 成绩权重一致性治理
```

## 10. 完成定义

死字段移除 + 单一权重口径 + 陈旧数据修正 + 迁移链完整 + 全量测试通过 + §7 验收通过，全部成立才可标记完成。

## 依赖

- **前置于 FIX-002 / FIX-003 / FIX-005（成绩导入）**：权重统一后，排名、GPA、成绩导入的正确性验收才有稳定基线。
- 被 FIX-002/003 引用的「排名/GPA 与数据库一致」断言，应以本 FIX 修正后的数据为基准。
