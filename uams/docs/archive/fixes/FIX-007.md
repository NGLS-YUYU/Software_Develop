# FIX-007：部署优化 + 排课联调收尾

## 1. 来源

- 对应 TASK：TASK-012（完善开课计划与教学班管理）+ TASK-013（教学安排与课表管理）
- 对应 RE-AUDIT 问题：问题 F（部署/启动收尾）+ 问题 G（排课 API 平铺 vs 嵌套、前端联调收尾）

## 2. 当前状态

**已有代码（后端，真实可用）：**

| 域 | 位置 | 内容 |
| --- | --- | --- |
| 排课（嵌套） | `app/api/v1/teaching.py` | `GET/POST /teaching-classes/{id}/schedules`、`PUT/DELETE /teaching-classes/{id}/schedules/{sid}` |
| 排课（平铺） | `app/api/v1/teaching_schedule.py` | `GET /teaching-schedules`、`PUT /teaching-schedules/{id}`（存在但前端未用） |
| 学生课表 | `app/api/v1/teaching_schedule.py` | `GET /teaching-schedules/mine` / `my` |
| 教师课表 | 同上 | 教师按教学班查询授课课表 |

**已有前端：**

- `admin/Teaching.vue` 走**嵌套**端点 `teachingApi`（`/teaching-classes/{id}/schedules`）管理排课，功能正常；
- 学生/教师课表页已存在路由（student/schedule、teacher/schedule），但**未接入 `teachingScheduleApi`（`/teaching-schedules/mine|my`）**。

**缺失部分：**

1. 平铺排课 API（`/teaching-schedules`）无前端入口，`api/index.ts` 无 `teachingScheduleApi`；
2. 学生「我的课表」、教师「我的授课」尚未调用真实排课数据源，可能为占位/假数据；
3. 部署收尾项：`start.sh` / 监听 `0.0.0.0` / `DEPLOYMENT.md` 未落实。

## 3. 修复目标

A. **部署**：提供 `start.sh`（后端 uvicorn 监听 `0.0.0.0` + 前端 dev/build 指引）、`DEPLOYMENT.md`（环境变量、MySQL 初始化、迁移、启动顺序、默认账号）。
B. **排课联调**：学生「我的课表」与教师「我的授课」接入真实 `GET /teaching-schedules/mine|my`；如需平铺排课管理则接入 `GET /teaching-schedules`，否则在文档中明确以嵌套端点为准，消除「两端点并存、前端只用一个」的歧义。

## 4. 不在本 FIX 范围内

- 不改排课业务规则（时间冲突、教室占用、周次/节次校验，已通过验收）；
- 不新增排课维度或课表导出；
- 不重建前端整体——只补部署脚本/文档 + 排课数据源联调。

## 5. 需要修改的文件

- 部署：`uams/backend/start.sh`（新建）、`uams/docs/DEPLOYMENT.md`（新建）、`uams/backend/app/main.py` 或启动入口（确认 host `0.0.0.0`）
- 前端 API：`frontend/src/api/index.ts`（新增 `teachingScheduleApi.mine/my`，必要时 `list`）
- 前端页面：`frontend/src/views/student/Schedule.vue`、`frontend/src/views/teacher/Schedule.vue`（接入真实数据）
- `frontend/src/types/index.ts`（补排课返回类型，若缺）

## 6. 实现要求

- `start.sh`：激活 venv → 加载 `.env` → `uvicorn app.main:app --host 0.0.0.0 --port 8000`；前端 `npm run dev` / `npm run build` 说明；
- `DEPLOYMENT.md`：MySQL 8.4 建库/账号、Alembic 迁移（禁止删历史）、`.env` 必要项、启动顺序、默认账号（admin/admin123、T001/T001、20260001/20260001）、常见问题；
- 学生/教师课表：直接取 `/teaching-schedules/mine|my`，无数据时显示空态，不渲染假数据；
- 平铺 vs 嵌套：以现有 UI 实际用法为准，在文档中说明取舍，不重复造两套前端入口。

## 7. 验收标准

```
执行 start.sh → 后端监听 0.0.0.0:8000，可访问 /docs
按 DEPLOYMENT.md 从零初始化 MySQL + 迁移 + 启动 → 三个默认账号可登录
学生登录 → 「我的课表」→ 显示与 /teaching-schedules/mine 一致的真实排课（含周次/节次/教室/教师）
教师登录 → 「我的授课」→ 显示与 /teaching-schedules/my 一致的真实排课
无排课学生 → 空态不报错
```
