# FIX-006：学期管理前端闭环

## 1. 来源

- 对应 TASK：TASK-011（学期与开课管理）
- 对应 RE-AUDIT 问题：问题 E（学期管理前端缺失）

## 2. 当前状态

**已有代码（后端，真实可用）：**

| 层 | 位置 | 内容 |
| --- | --- | --- |
| Model | `app/models/term.py` | `AcademicTerm`（name/academic_year/semester(1|2)/start_date/end_date/status） |
| Service | `app/services/term.py` | CRUD + `activate`/`end`（PLANNED→ACTIVE→ENDED 单向，单激活约束） |
| API | `app/api/v1/terms.py` | `GET/POST /terms`、`GET/PUT/DELETE /terms/{id}`、`POST /terms/{id}/activate|end` |
| 权限 | `term:read` / `term:write` | 仅 ACADEMIC_ADMIN 可写 |

**已有前端：无。** `api/index.ts` 无 `termApi`；无学期管理页；学期在 Teaching.vue / SelectionManage.vue 仅以**字符串下拉**（`semesterOptions()`）出现，非 `AcademicTerm` 实体。

**缺失部分：** 学期实体（学年/学期/起止日期/状态/激活/结束）的管理入口全缺失。

## 3. 修复目标

教务管理员在「学期管理」页查看/新增/修改/删除学期，并对 PLANNED 学期「激活」、对 ACTIVE 学期「结束」，状态单向流转、全局最多一个 ACTIVE，操作真实落库。

## 4. 不在本 FIX 范围内

- 不改后端 `/terms` 业务规则（唯一约束、单激活、单向流转，已通过验收）；
- **不新增复杂功能**（如自动生成学年、跨学期复制等）——以现有 PRD/代码为准；
- 不改动现有「semester 字符串」下拉在开课/选课页的用法（其与 AcademicTerm 的映射是否统一，如发现不一致单独报告）。

## 5. 需要修改的文件

- `frontend/src/api/index.ts`（新增 `termApi`：list/create/update/remove/activate/end）
- `frontend/src/router/index.ts`（新增 `/admin/terms` 路由 + 菜单）
- `frontend/src/views/admin/Terms.vue`（新建）
- `frontend/src/types/index.ts`（补 Term 类型，若缺）

## 6. 实现要求

- 列表显示：名称/学年/学期序号/起止日期/状态/教学班数；
- 新增/编辑表单：name / academic_year / semester(1|2) / start_date / end_date；前端校验 end_date > start_date（后端仍最终校验）；
- 状态操作：PLANNED → 激活；ACTIVE → 结束；ENDED 只读，不可再改状态；
- 后端错误（如「已存在进行中学期」）由拦截器透出提示。

## 7. 验收标准

```
登录 admin → 学期管理 → 新增学期（PLANNED）→ POST /terms → MySQL academic_terms 新增
→ 激活该学期 → POST /activate → status=ACTIVE（若已有 ACTIVE 则 409）
→ 结束学期 → POST /end → status=ENDED → 之后增删改返回 409（只读）
→ 刷新列表数据正确
```
