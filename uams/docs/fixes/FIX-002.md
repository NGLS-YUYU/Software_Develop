# FIX-002：排名展示闭环

## 1. 来源

- 对应 TASK：TASK-004（GPA-like 学分绩点系统）
- 对应 RE-AUDIT 问题：问题 B（排名前端缺失）

## 2. 当前状态

**已有代码（后端，真实可用）：**

| 层 | 位置 | 内容 |
| --- | --- | --- |
| 绩点换算 | `app/models/grade.py` | `score_to_point`（90-100→4.0 … <60→0） |
| GPA | `app/services/gpa_service.py` | 学分加权 GPA = Σ(绩点×学分)/Σ学分 |
| 排名 | `app/services/ranking_service.py` | 班级排名 / 专业排名 |
| API | `app/api/v1/grade.py` | `GET /grades/my` → `{ items, gpa, class_rank, major_rank }` |

**实测证据**：`GET /grades/my` 返回 `gpa=2.78、class_rank=5、major_rank=5`（真实数据）。

**已有前端：** `student/Grades.vue` 只显示「平均绩点」（经 `gradeApi.mySummary()`），**不展示班级/专业排名**，且**未调用 `/grades/my`**。

**缺失部分：** 排名展示 UI + 前端对 `/grades/my` 的调用。

## 3. 修复目标

学生在「我的成绩」页看到真实计算的**班级排名**与**专业排名**（含 GPA）。数据来源为后端 `/grades/my`，前端只负责展示，**禁止前端自行计算排名**。

## 4. 不在本 FIX 范围内

- 不重写 GpaService / RankingService / score_to_point（已通过验收）；
- 不新增排名规则或排名维度（如年级排名、全院排名）——除非 PRD 明确要求；
- 排名计算正确性依赖 FIX-008（成绩权重统一），但**权重治理不在本 FIX 内**，本 FIX 只做展示接入。

## 5. 需要修改的文件

- `frontend/src/api/index.ts`（新增 `gradeApi.my()` 调用 `/grades/my`，若缺）
- `frontend/src/views/student/Grades.vue`（新增排名展示区块）
- `frontend/src/types/index.ts`（补 `gradeApi.my` 返回类型，若缺）

## 6. 实现要求

- 在「我的成绩」页新增「我的排名」卡片：显示 `gpa`、`class_rank`、`major_rank`（若为 null 则显示「暂无」）；
- 排名展示值直接取 `/grades/my` 返回值，不在前端重算；
- 与既有 `mySummary` 的「平均绩点」保持口径一致（二者应同源同值；若发现不一致，报告并交 FIX-008）。

## 7. 验收标准

```
登录学生 → 进入「我的成绩」→ 看到 平均绩点 / 班级排名 / 专业排名
→ 数值与 GET /grades/my 返回一致 → 与数据库真实成绩计算一致
→ 无成绩学生：gpa/class_rank/major_rank 显示「暂无」不报错
```

## 8. 测试要求

- API 测试：`test_gpa_ranking.py` 已有排名计算断言，扩展断言 `/grades/my` 返回结构与排名顺序正确；
- 前端：`vue-tsc --noEmit` 通过；
- E2E/手工：用多名真实学生核对排名顺序与 GPA 一致。

## 9. Git 提交要求

```
fix(FIX-002): 学生端排名展示闭环
```

## 10. 完成定义

代码 + 测试 + 排名前端展示 + 与后端/数据库一致 + §7 验收通过，全部成立才可标记完成。
