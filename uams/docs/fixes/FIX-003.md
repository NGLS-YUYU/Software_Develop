# FIX-003：学生成绩 / GPA / 排名闭环

## 1. 来源

- 对应 TASK：TASK-007（学生查询系统）
- 对应 RE-AUDIT 问题：问题 B（排名前端缺失）

## 2. 当前状态

**已有代码（后端，真实可用）：**

- `GET /grades/mine`（仅 APPROVED 成绩，按学期）
- `GET /grades/mine/summary`（已修学分/平均绩点/已修课程/不及格）
- `GET /grades/my`（成绩 + gpa + class_rank + major_rank）

**已有前端：** `student/Grades.vue` 展示成绩明细（平时/期末/总评/绩点/结果）与统计卡片（已修学分/平均绩点/已修课程/不及格）。

**缺失部分：** 班级/专业排名展示缺失；成绩链路（总评→绩点→GPA→排名）的统一规则未在前端展示层面闭环。

## 3. 修复目标

学生端「我的成绩」完整呈现：成绩明细 → 最终成绩 → 绩点 → GPA → 班级排名 → 专业排名，全程数据统一来自后端（`/grades/my`），前端只做展示。

## 4. 不在本 FIX 范围内

- 不重写成绩计算（ScoreService）、GPA、排名（GpaService/RankingService）；
- **权重规则统一（32h/48h/64h）归 FIX-008**，不扩大本 FIX 范围；本 FIX 只确保「展示链路」正确引用统一规则的结果。

## 5. 需要修改的文件

- `frontend/src/api/index.ts`（确保 `gradeApi.my()` 存在并调用 `/grades/my`）
- `frontend/src/views/student/Grades.vue`（排名展示；与 FIX-002 可能同文件，注意合并避免重复改动）
- `frontend/src/types/index.ts`（补返回类型，若缺）

## 6. 实现要求

- 学生成绩页在现有统计卡片基础上，补充 `class_rank` / `major_rank`；
- 明确「平均绩点」与「GPA」来自同一后端口径，避免两处数值不一致；
- 若发现 32h/48h/64h 权重在展示链路上产生与后端不一致的结果，**报告并转 FIX-008**，不得在本 FIX 内私自调整计算。

## 7. 验收标准

```
登录学生 → 「我的成绩」→ 成绩明细、绩点、GPA、班级排名、专业排名齐全
→ 各数值与 GET /grades/my 一致，且与 MySQL 真实成绩按统一权重计算一致
```

## 8. 测试要求

- 复用/扩展 `test_student_grade.py`：断言 `/grades/my` 的 gpa/排名与 RankingService/GpaService 一致；
- 前端 `vue-tsc --noEmit` 通过；
- E2E/手工：用带真实成绩的学生核对整条链路数值。

## 9. Git 提交要求

```
fix(FIX-003): 学生成绩GPA排名展示闭环
```

## 10. 完成定义

成绩 → 绩点 → GPA → 排名 在真实数据上闭环展示、与后端/数据库一致、§7 验收通过，全部成立才可标记完成。
