# FIX-001：用户管理前端闭环

## 1. 来源

- 对应 TASK：TASK-001（用户权限体系完善）
- 对应 RE-AUDIT 问题：问题 A（用户管理前端缺失）

## 2. 当前状态

**已有代码（后端，真实可用）：**

| 层 | 位置 | 内容 |
| --- | --- | --- |
| Model | `app/models/user.py` | `User`（username/real_name/user_type/status/last_login_at） |
| Service | `app/services/user.py` | `paginate` / `get_or_404` / `create_user` / `reset_password` / `set_status` |
| API | `app/api/v1/user.py` | `GET /users`、`GET /users/{id}`、`POST /users`、`PUT /users/{id}/password`、`PUT /users/{id}/status` |
| 权限 | `user:read` / `user:write` | 仅 ACADEMIC_ADMIN |

**已有前端：无。**

- `frontend/src/api/index.ts` 无 `userApi`；
- `frontend/src/router/index.ts` 无 `/admin/users` 路由；
- 无用户管理页面；菜单无「用户管理」项。

**缺失部分：** 前端入口全部缺失——用户列表、查询、新增、重置密码、停用/启用均无法从界面操作。

## 3. 修复目标

教务管理员（ACADEMIC_ADMIN）登录后，可进入「用户管理」页面：查看/筛选用户列表（按类型、状态、关键词），新增账号（按 user_type 分配角色）、重置密码、停用/启用账号；操作后数据真实落库，刷新页面结果仍正确。

## 4. 不在本 FIX 范围内

- **不改后端** `/users` 的现有逻辑（已通过验收），除非接入时发现确凿缺陷并单独报告；
- **不新增角色/权限码**；复用 `user:read` / `user:write`；
- **「编辑用户基本信息」与「删除用户」**：当前后端无 `PUT /users/{id}`（基本信息）与 `DELETE /users/{id}` 端点。[NEEDS_CONFIRMATION] —— 需确认 PRD 是否要求；PRD §10 无独立「用户管理」条目（§10.2/10.3 学生/教师管理会联动创建用户），故本 FIX 只闭环「列表/查询/新增/重置密码/停用启用」，编辑与删除是否补做留待确认。

## 6. 实现要求

- 复用 `useCrudTable` 组合式函数与既有页面风格（参照 `Students.vue` / `Teachers.vue`）；
- 新增用户表单：`username` / `real_name` / `user_type`（STUDENT/TEACHER/ADMIN）/ `password`（≥6 位）/ `role_codes`（为空按 user_type 默认角色）；
- 重置密码与停用/启用作为行内操作，带二次确认；
- 权限：菜单与路由仅对 ADMIN 显示；后端 `user:read`/`user:write` 仍为最终校验；
- 不实现前端「角色权限自由编辑」——角色分配以后端 `role_codes` 为准，若 PRD 未要求角色管理界面则不做。

## 7. 验收标准

```
登录 admin → 进入「用户管理」→ 新增一个用户（STUDENT）→ POST /users → MySQL users 表出现记录
→ 刷新列表可见 → 停用该用户 → PUT /users/{id}/status → DB status=DISABLED
→ 重置密码 → 新密码可登录
→ 越权：teacher/student 访问 /users 返回 403
```
