# FIX-004：必修课预安排前端闭环

## 1. 来源

- 对应 TASK：TASK-009（必修课自动安排 + 选修课选课）
- 对应 RE-AUDIT 问题：问题 C（必修课预安排前端缺失）

## 2. 当前状态

**已有代码（后端，真实可用）：**

| 层 | 位置 | 内容 |
| --- | --- | --- |
| API | `app/api/v1/teaching.py` | `POST /teaching-classes/{class_id}/assign-required`（范围优先级 class_id > major_id > college_id，幂等） |
| Service | `app/services/selection.py` | `assign_required`（按学院/专业/行政班筛选学生批量建立 CourseSelection） |
| 权限 | `selection:manage` | 仅 ACADEMIC_ADMIN |

**已有前端：** `student/Selection.vue`（选修课选/退，经 `selectionApi.select/drop`）正常。

**缺失部分：** 前端无 `assignRequired` 调用、无「必修课预安排」按钮/表单，教务无法从界面发起必修课预安排。

## 3. 修复目标

教务管理员在选课管理（或教学班）界面，对必修课教学班发起「预安排」，指定范围（学院/专业/班级，优先级 class_id > major_id > college_id），学生端自动获得必修课选课记录；同时不破坏现有选修课选退流程，学生仍不能绕过规则选择不允许选择的课程。

## 4. 不在本 FIX 范围内

- 不改后端 `assign_required` 业务逻辑（已通过验收）；
- 不重做选修课选退（已正常）；
- 不新增「必修课/选修课」边界定义——以现有 `Course.course_type`（REQUIRED/PUBLIC_REQUIRED/PRACTICE 为必修，ELECTIVE/PUBLIC_ELECTIVE 为选修）为准；若发现边界歧义，标记 [NEEDS_CONFIRMATION]。

## 5. 需要修改的文件

- `frontend/src/api/index.ts`（新增 `teachingApi.assignRequired(classId, scope)` 或并入 selectionApi）
- `frontend/src/views/admin/SelectionManage.vue`（或 `Teaching.vue`，预安排操作入口）
- `frontend/src/types/index.ts`（补请求/响应类型，若缺）

## 6. 实现要求

- 预安排操作仅对「必修课教学班」开放入口（前端判断 course_type；后端 `assign_required` 仍做最终校验）；
- 表单提供范围选择：`college_id` / `major_id` / `class_id`（至少其一），并展示范围优先级说明；
- 调用真实 `POST /teaching-classes/{class_id}/assign-required`，展示返回 `{matched, assigned, skipped}`；
- 不改动学生选修课选退逻辑与「学生不能选必修课/不允许的课程」的现有后端校验。

## 7. 验收标准

```
登录 admin → 选课管理 → 对必修课教学班点「预安排」→ 选择学院/专业/班级范围
→ POST assign-required → MySQL course_selections 新增必修选课记录
→ 学生端「我的课程/课表」出现该必修课 → 重复预安排幂等（不产生重复记录）
→ 学生仍无法自行选必修课/不允许的课程（后端 409）
```

## 8. 测试要求

- API 测试：`test_selection.py` 已有 assign-required 覆盖，扩展前端联调后的回归；
- 前端 `vue-tsc --noEmit` 通过；
- E2E/手工：按 §7 完整走通，核对数据库选课记录数与幂等。
