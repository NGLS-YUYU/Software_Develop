## 3. 学生 / 教师 / 课程批量导入

三者共用一条链路：**下载模板 → 填写 → 上传 → 逐行校验 → 部分成功 + 错误明细**。

- 模板首行是**中文字段名**（`学号/姓名/学院/…`），同时**兼容旧的英文字段名**（`student_no` 等），既有调用方与旧模板不受影响。
- 取值支持中文：职称 `教授/副教授/讲师/助教`、性别 `男/女/未知`、课程性质 `专业必修/…`（后端翻译为枚举，非法值报错并给出可填值）。
- 模板第 2 个工作表是「填写说明」，逐条说明必填项与常见错误；**说明不放在数据行**，避免被解析成数据。
- **教师导入为本 FIX 新增**：`工号 = 登录名`，初始密码 = 工号（复用 `TeacherService.create_teacher`，不重复实现用户/RBAC 创建）。
- **课程导入与网页创建共用同一套校验**：`理论学时 + 实践学时 = 总学时` 由 `CourseService.create` 统一把关，Excel 无法绕过；考核方式由 `total_hours` 推导，**模板不提供该列**（FIX-009 规则未被破坏，也未重新引入 40/60 旧口径）。

## 4. 成绩批量导入（核心）

### 4.1 模板由后端按教学班动态生成

`GET /imports/templates/grades?teaching_class_id=N`：

| 课程 | 成绩列（由后端 `AssessmentProfile` 决定） |
|---|---|
| ≤32 学时、无实践 | 平时成绩、期末成绩 |
| ≤32 学时、有实践 | 平时成绩、期末理论、期末实践 |
| >32 学时、无实践 | 平时成绩、期中成绩、期末成绩 |
| >32 学时、有实践 | 平时成绩、期中理论、期中实践、期末理论、期末实践 |

- 固定列（**系统生成、教师不用填也不该改**）：学号、姓名、班级、课程代码、课程名称、教学班（灰底提示）。
- 补考列：非实践课为「补考成绩」；实践课为「理论补考 + 实践补考」。
- 名单取自教学班已选学生；**已有草稿成绩回填**，教师在其基础上修改后重新上传即可。
- **Vue 中没有任何 32/48/64 判断**，前端只渲染后端给的列。

### 4.2 Excel 不是第二套计算系统

模板只录入原始成绩；总评 / 理论总评 / 实践总评 / 绩点 / 是否及格全部由 `ScoreService` 在导入时统一计算（`GradeService.import_scores` → `compute_for_draft`），结果一律落为 **DRAFT**，不写 GPA / 排名。

### 4.3 错误处理与事务策略

沿用项目既有的**部分成功（Strategy B）**策略，未改变既有设计：合法行入库，非法行返回 `{row, field, message}`，前端渲染为「Excel 行号 / 出错列 / 原因」表格。

导入校验（每行取首个错误）：学号存在 → 教学班存在 → **学生属于该教学班** → 成绩未被提交/审核 → 0-100 范围 → 理论/实践成对 → 实践成绩与 `practice_hours` 匹配（FIX-009）→ 补考只在期末分项 < 60 时允许 → **教师只能导入本人授课教学班**。

## 5. 成绩草稿删除

- `DELETE /api/v1/grades/{grade_id}`，成功 204。
- **只有 `DRAFT` 可删**；`SUBMITTED` / `APPROVED` / `REJECTED` 一律 409。草稿与正式成绩共用 `grades` 表，删除严格依赖 `status == DRAFT`，**不按 id 直删**。
- 教师只能删本人教学班的草稿（403）；教务可删任意草稿；学生 403。
- 前端：行内「删除草稿」按钮（非草稿自动禁用）+ `ElMessageBox` 二次确认 + 删除后刷新列表。
- 注：`REJECTED` 按工单 §十三「只有 DRAFT 允许删除」字面执行也一并拒绝（409）——已驳回成绩已进入过提交链路，删除会破坏留痕。
